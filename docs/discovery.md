# Search and catalog pages

`GET /api/games?q=...&cursor=...` returns `{ games, nextCursor }`. Pages contain at most 24 games. A null cursor means the end of the matching catalog. Search is an optional trimmed literal substring (case-insensitive) in title or description, up to 80 characters. Regex metacharacters are escaped; users cannot supply a database regex. Unknown parameters and malformed/mismatched cursors receive 400.

Only published, unsuspended projects with a publication timestamp are listed. Responses select public game metadata, not owner identifiers or internal notes. Ordering is newest publication first with descending UUID as the tie-breaker. The cursor retains the timestamp/UUID boundary and search text; it is an untrusted pagination hint, not an access credential. Page queries use this boundary instead of an offset, and reapply visibility checks on every page. App rate limits and no-store headers still apply.

The frontend debounces search, discards superseded responses, resets pagination on query changes, deduplicates appended records by ID, exposes loading and retry states, and offers Load more games. Saved-game filtering remains local to the private bounded library. Loaded counts are counts of returned games, not popularity or engagement.

This is a live catalog, not a snapshot: publishing/restoring while someone browses may move a game before their cursor. A fresh search/reload returns the current first page. The UI removes duplicate IDs, but cannot promise a perfectly frozen multi-page view during concurrent changes. Existing running-game access is not determined by a discovery listing; launch and SDK checks remain separate.

The ordered catalog has a compound index. Substring search can still scan many indexed candidates and is capped by a two-second database execution limit, returning a retryable 503 if exceeded. This is not a production-scale search/capacity claim. A larger catalog will need measured load testing and an indexed search service/strategy. No search queries are added to analytics by this implementation. The cursor encodes the search text, so deployments must avoid retaining query strings in access logs when search privacy matters.

Local tests cover 75 records with identical timestamps, all pages without duplicate/missing IDs, hidden drafts/suspensions, database-wide case-insensitive search, regex literal treatment, invalid cursor/query inputs and visibility changes between pages. A disposable browser catalog uses 30 explicitly labeled independently playable starter copies only when the test preview requests them. The real UI checks first-page/next-page/end states, search beyond the first page, literal regex-like input, clearing search and rapid query changes. These fixtures never run in production or seed real activity.
