# Account integration

Initialize with `await createAuth({db, config, sendMail})`. Mount `router` at `/api/auth`. All mutation requests require an `Origin` header matching `config.appOrigin`. Mount `authenticate` and `requireUser` on protected routes. `req.user` is internal and must never be serialized directly; use `publicUser`. WebSocket upgrades use `resolveSession(request.headers.cookie)` and independently validate the Origin. Revalidate active sockets periodically to enforce resets/suspensions after upgrade.

Registration accepts username, email, password, dateOfBirth (YYYY-MM-DD). Login accepts identifier (username or email) and password. Public user responses include id, username, emailVerified, ageBand, role and avatar. Forgotten password accepts email; reset-password accepts token/password; verify-email accepts token. Resend-verification requires a session. Email URLs use fragments, which the client must consume, immediately remove from browser history, and submit to the corresponding endpoint. Never add analytics to recovery flows.

Email delivery is injected as an async `sendMail({to, subject, text, signal})`; providers should honor the abort signal and set their own network timeouts. Absent delivery disables recovery and verification rather than exposing tokens or claiming mail was sent. Production requires a functioning transactional email provider. Requests enqueue durable Mongo outbox jobs without waiting for delivery. Recovery performs the same enqueue operation for known and unknown emails, with account lookup and eligibility checks deferred to the worker; provider timing and delivery errors cannot distinguish accounts in the HTTP response. Email links expire (reset 30 minutes; verification 24 hours); token hashes alone are stored.

Run `await drainMailOutbox({db, sendMail, limit: 10})` at startup and roughly every 30 seconds. Workers atomically acquire two-minute leases; concurrent workers cannot acquire an active lease. Abandoned leases are recoverable. Delivery has a 30-second timeout and five-attempt exponential backoff (30 seconds up to 15 minutes), bounded by a 30-minute job lifetime and TTL cleanup. One recipient/purpose job per 15-minute bucket limits repeated requests; IP limits apply before enqueue, including unknown addresses. Completion removes recipient information from the job. The worker returns counts only, never provider errors, message text or token values. Tokens are generated in worker memory, not stored in outbox payloads. Access to both collections must be restricted.

Delivery is at least once: if a worker crashes after a provider accepts mail but before completion is persisted, a retry may deliver another valid link. A provider that ignores cancellation may also complete after timeout. This is a standard cross-system delivery ambiguity; exactly-once delivery is not promised. Monitor failed jobs and delivery counts. Shared rate limiting is still needed to contain distributed abuse and outbox growth across instances.

Password hashing uses Node crypto scrypt with N=131072, r=8, p=1, a random 128-bit salt and 512-bit output; hashing concurrency is limited to two to bound memory. HTTP limits are per-process/IP; multi-instance deployments must add a shared rate-limit store and distributed account-based throttling. Passwords support 15–128 characters without arbitrary composition rules. A compromised-password screening provider/list is a remaining production hardening step.

Opaque 256-bit sessions are hashed in MongoDB, expire explicitly at query time, and also have a Mongo TTL index for cleanup. Login rotates the current session. Reset atomically increments the account's authVersion, invalidating all prior sessions even if subsequent cleanup fails. Production uses a Secure, HttpOnly, SameSite=Strict, Path=/ cookie with a __Host- prefix. Production must use HTTPS and correctly configured trusted proxies.

Birth dates are validated server side but are self-declared, not verified age assurance. Under-13 registrations are rejected. Adults retain only their age band. Teens retain their 18th-birthday transition date, which still indirectly reveals DOB; limit access and treat it as sensitive. On authenticated access after the transition, that date is erased and the age band changes to adult. Separate moderation, chat, advertising and entitlement layers must actually enforce teen restrictions. No self-service role or emailVerified changes exist. Admin bootstrap must be an explicit operator-controlled action.

Security sources: [OWASP password storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [session management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), and [password recovery](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html). This module is a tested foundation, not a claim that all launch controls or legal age-assurance obligations are complete.
