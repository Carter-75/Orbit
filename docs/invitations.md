# Friend-to-game invitations

The trusted Orbit page shows Play with friends. After a published game joins a room through the SDK, choose an accepted friend and send a game invitation. Preview rooms cannot send invitations. Recipients refresh their invitations or receive the next visible-page refresh, then choose Join friend or Decline. Joining launches the published build and asks the SDK bridge to connect to the invited room.

Each invitation expires after five minutes. Creation and acceptance recheck the inviter's live room membership, active session, launch grant, multiplayer capability, current published build, capacity and verified eligible friendship. Both accounts must be in the same age band; blocks, suspensions, age transitions, ended rooms, outdated builds and revoked sessions make the invitation unavailable. The recipient must own the invitation and only one acceptance can succeed. The routing response is not a credential or reserved seat: the normal launch and WebSocket join paths still enforce access and capacity. If a room fills or changes while launching, the game receives a normal room error and the player can ask for a new invitation.

Server storage uses expiring MongoDB records. Reads enforce expiry even before MongoDB cleanup. At most 50 current incoming records are considered per refresh. Sending is limited to ten per account per minute. Pending list responses omit room codes, grants, and private account details. No email or external message is sent; this is entirely inside Orbit.

Tests use real disposable MongoDB and a controlled room directory to verify non-friend denial, recipient isolation, concurrent single acceptance, expiry, blocking, age transition, revoked sender session, preview rejection, capacity, room termination and decline. Separate realtime tests exercise actual WebSocket access and synchronization. Browser invitation-to-game end-to-end verification remains required; these backend tests do not prove that the UI/SDK automatic join works. Single-server room routing remains a deployment constraint.
